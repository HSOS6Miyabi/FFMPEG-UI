# 程序结构

## 总体设计

程序分为平台界面、任务控制、媒体转换和压缩包处理四部分。Windows 与 Linux 共用任务队列、资源调度、FFmpeg 参数生成、ZIP 读写和输出检查代码。

```text
┌─────────────────────┐       ┌─────────────────────┐
│ Windows：Win32/GDI  │       │ Linux：X11/Xft      │
└──────────┬──────────┘       └──────────┬──────────┘
           └──────────────┬──────────────┘
                          │
                ┌─────────▼─────────┐
                │   AppController   │
                │ 批量任务与资源调度 │
                └───────┬───────────┘
                        │
            ┌───────────┴────────────┐
            │                        │
   ┌────────▼────────┐      ┌────────▼────────┐
   │  FfmpegService  │      │  ArchiveService │
   │ 视频编码与验证  │      │ ZIP / PPTX 处理 │
   └────────┬────────┘      └────────┬────────┘
            │                        │
            └───────────┬────────────┘
                        │
                ┌───────▼────────┐
                │  ProcessRunner │
                │ 子进程和进度读取 │
                └───────┬────────┘
                        │
                  ffmpeg / ffprobe
```

## 输入与任务队列

`AppController::addInputs` 接收命令行参数、文件对话框和拖放事件传入的路径。

- 如果路径是文件夹，程序根据递归扫描设置查找视频、ZIP 和 PPTX。
- 如果路径是文件，程序根据扩展名确定任务类型。
- 程序会对路径进行规范化并去重，避免重复加入同一文件。
- 每个独立视频作为一个任务；ZIP 和 PPTX 作为一个容器任务，并在展开后建立内部视频项目列表。
- 每个任务保存输入路径、输出路径、相对目录、状态、进度、输入大小、输出大小和错误信息。
- 任务清单使用 UTF-8 的 `.ffq` 文件，每行记录一个输入路径。导入时复用同一套路径去重和文件夹扫描逻辑。
- 用户的编码参数和输出目录保存在系统用户配置目录中。Windows 使用 `%APPDATA%\FFmpeg Studio\settings.ini`，Linux 使用 `$XDG_CONFIG_HOME/ffmpeg-studio/settings.ini` 或 `$HOME/.config/ffmpeg-studio/settings.ini`。

## 资源调度

`recommendResourcePlan` 根据逻辑 CPU 核心数、当前可用物理内存、编码器类型和待处理项目数量计算并行任务数。

- CPU H.264/H.265 按每个任务约 2 GiB 内存估算；CPU AV1 使用约 3 GiB 的估算值。
- 硬件编码按每个任务约 1.5 GiB 内存估算，并默认最多并行两个编码任务。
- CPU 编码会把全部逻辑核心纳入调度，根据任务数量和可用内存分配并行任务数及每个进程的线程数。
- 每个 FFmpeg 进程都会收到独立的 `-threads:v` 数值。自动模式使用向上取整分配线程，尽量让总线程数覆盖全部逻辑核心。
- 用户可以设置最大并发任务数。自动模式会根据实际任务数量重新计算。
- 当一个 ZIP 或 PPTX 是唯一的顶层任务时，容器内部视频会使用资源调度器计算的并发数并行转换。

该估算用于平衡 CPU 和内存占用。硬件编码器的显存占用和并发会话限制由显卡驱动及 FFmpeg 运行结果进一步约束。

## 视频转换

`src/core/conversion.cpp` 负责：

- 根据编码格式和设备选择 `libx264`、`libx265`、`libsvtav1`、`libaom-av1`、NVENC、Quick Sync 或 AMF 编码器。
- 将 CRF、八档压缩级别、音频码率和每个任务的线程数转换为 FFmpeg 参数。
- 使用 `-progress pipe:1` 读取结构化进度。
- 使用 ffprobe 读取视频时长、输出编码和容器标记。
- 为输出文件写入参数指纹，并在重复处理时检查该指纹。
- 先写入临时文件，检查通过后再保存到最终位置。

`src/core/process.cpp` 负责启动外部程序、读取标准输出和标准错误，并处理暂停、继续和取消操作。

Linux 使用 `posix_spawnp` 启动子进程，并将子进程放入独立进程组。暂停时向进程组发送 `SIGSTOP`，继续时发送 `SIGCONT`。Windows 使用 `CreateProcessW`，暂停时暂时挂起 FFmpeg 进程的线程，继续时恢复线程。程序通过 UTF-16 命令行传递 Unicode 路径，不会通过 shell 拼接 FFmpeg 命令，路径和参数始终作为独立参数传递。

## ZIP 和 PPTX 处理

`src/core/archive.cpp` 使用 libarchive 读取和生成 ZIP 文件。PPTX 使用 ZIP 容器，因此共用同一套归档处理逻辑。

1. 检查 ZIP 条目路径，拒绝绝对路径、路径穿越、符号链接和硬链接。
2. 限制 ZIP 条目数量、单文件展开大小和总展开大小。
3. 将压缩包展开到独立临时目录。
4. 扫描常见视频扩展名，建立内部视频任务列表。
5. 根据资源计划并行调用 `FfmpegService`，按当前输出容器设置生成视频。
6. 将原视频替换为 MP4。如果扩展名发生变化，记录旧路径和新路径。
7. 更新常见文本、XML、网页文件中的视频路径。
8. 对 PPTX，进一步更新幻灯片关系文件的 `Target`，并在 `[Content_Types].xml` 中声明对应的媒体内容类型。
9. 写入压缩包处理记录，重新生成 ZIP/PPTX。
10. 重新读取输出文件，检查 ZIP 完整性；PPTX 还要检查 `[Content_Types].xml` 和 `ppt/presentation.xml`。
11. 只有检查通过后，才将临时压缩包保存为最终输出文件。

如果任何一个内部视频转换失败，程序会放弃当前临时压缩包，保留原始 ZIP/PPTX。

## 重复处理检查

独立视频会在 MP4 的 `comment` 元数据字段中记录编码参数指纹。指纹包括编码格式、编码设备、质量数值、压缩级别和音频码率，不包含线程数量，因为线程分配不会改变用户选择的编码质量设置。

ZIP/PPTX 会在内部写入处理记录，其中包含输入文件大小、修改时间和参数指纹。再次处理相同输入时，如果记录完全相同，程序会跳过整个容器任务。

## 输出文件保护

独立视频会先写入目标目录中的唯一临时 MP4 文件。FFmpeg 成功退出后，程序使用 ffprobe 检查容器、视频编码、音频编码和参数标记。检查通过后，才会将临时文件移动到最终路径。

ZIP/PPTX 也会先在临时目录中完成展开、视频转换和重新打包。输出压缩包通过完整性检查后，才会保存到目标位置。

用户取消任务或转换失败时，程序会清理临时文件。用户已有的源文件会保留。

## 平台界面

### Windows

界面使用 Win32 窗口消息和 GDI 绘制，文件对话框使用 Windows 系统 API。应用清单启用 Common Controls v6、Per-Monitor V2 DPI 和长路径支持。界面使用 Segoe UI，并在支持的 Windows 版本启用 DWM 圆角、系统标题栏配色和 Mica 背景。程序支持文件拖放和多个命令行文件参数。

### Linux

界面使用 X11 窗口与事件接口，使用 Xft 和 Fontconfig 绘制抗锯齿文字，并根据 `Xft.dpi` 调整界面尺寸。支持 Xdnd 文件拖放。文件选择优先调用 `zenity`，未安装时尝试 `kdialog`；两者均不可用时，仍可以通过命令行传入路径。

## SSH 远程处理

`SshService` 读取并管理本机 SSH 配置，使用 OpenSSH 的 `ssh` 和 `scp` 执行远程连接与文件传输。`FfmpegService` 负责远程编码器探测、上传、远程 FFmpeg 进度读取、输出验证和下载。远程主机只承担视频转换工作，ZIP/PPTX 的展开、关系更新和重新打包仍在本机完成。远程任务使用独立临时目录；取消或完成后会尝试终止远程 FFmpeg 并删除临时目录。

## 外部依赖

- FFmpeg 和 ffprobe：通过命令行执行视频探测和编码，不直接链接 FFmpeg 动态库。
- libarchive：读取和生成 ZIP/PPTX。
- Linux：X11、Xft 和 Fontconfig。
- Windows：Win32、GDI、DWM、Shell 和 Common Controls 系统 API。

项目不使用 Qt、GTK、MFC 或 Electron 等桌面界面框架。
