# 项目决策记录

本文记录会影响后续开发和维护的设计选择。修改相关实现时，应先检查本文和对应测试，再同步更新代码、测试和说明文档。

## 项目技术方案

- 使用 C++20 实现共享编码核心和任务控制。
- Windows 使用 Win32 API 和 GDI 绘制界面；Linux 使用 X11 和 Xft 绘制界面。
- 不引入 Qt、GTK、MFC、Electron 或其他桌面界面框架。
- 使用 CMake 构建 Windows 和 Linux 版本。
- 使用 libarchive 读取和生成 ZIP/PPTX。该依赖只负责压缩包处理，不参与界面和视频编码。
- 通过 FFmpeg 和 ffprobe 命令行程序完成视频处理，不直接链接 FFmpeg 动态库。
- FFmpeg 由运行环境提供，不在程序中捆绑外部二进制文件。

## 编码器选择

- H.264 CPU 编码使用 `libx264`。
- H.265 CPU 编码使用 `libx265`。
- AV1 CPU 编码优先使用 `libsvtav1`，缺少该编码器时使用 `libaom-av1`。
- NVIDIA 硬件编码使用 `h264_nvenc`、`hevc_nvenc` 和 `av1_nvenc`。
- Intel Quick Sync 使用 `h264_qsv`、`hevc_qsv` 和 `av1_qsv`。
- AMD AMF 使用 `h264_amf`、`hevc_amf` 和 `av1_amf`。
- 启动时读取 FFmpeg 编码器列表，并对每个硬件编码器执行单帧测试。只有测试成功的编码器才会显示为可用。
- 编码器可用性必须按具体编码格式分别检查，不能因为某个硬件支持 H.264 就显示其 AV1 编码选项。

## 质量参数和压缩级别

- H.264 和 H.265 的质量数值范围为 0–51，AV1 为 0–63。
- CPU 编码使用 CRF；NVENC 使用 VBR `-cq`；Quick Sync 使用 `-global_quality`；AMF 使用 CQP `-qp_i` 和 `-qp_p`。
- 界面提供 CRF 滑块和数值输入框。命令生成器负责将统一的质量数值转换为各编码器支持的参数。
- 压缩级别固定为八档：极速、非常快、快速、均衡、慢速、较慢、很慢和极致压缩。
- CPU H.264/H.265 使用 x264/x265 预设；SVT-AV1 使用 `-preset`；libaom AV1 使用 `-cpu-used`。
- NVENC 使用 p1 至 p7，极致压缩档额外启用全分辨率 multipass。
- Quick Sync 使用其 `-preset` 选项和 `-global_quality`；较慢档位启用 look-ahead。
- AMD AMF 使用其支持的 speed、balanced、quality 预设和 CQP 参数。AMF 的多个相邻界面档位可能映射到同一个硬件预设。
- 新增或修改参数映射时，必须更新 `tests/core_tests.cpp` 和 `docs/encoding.md`。

## 视频裁剪与画面预览

- 两个平台的主窗口均提供可直接输入的起止时间字段；预览窗口用于根据画面选择起点和终点。点击时间轴和方向按钮跳转时，使用 FFmpeg 的输入侧 `-ss` 提取指定位置的画面。
- 裁剪时间保存在 `BatchSettings`，作为当前批次的统一设置。独立视频、ZIP/PPTX 内视频和 SSH 远程处理共用 `ConversionSettings` 的裁剪字段。旧设置文件缺少裁剪字段时，默认转换完整视频。
- 仅设置起始时间时，结束位置为片尾。设置结束时间时必须晚于起始时间；`-t` 在输入参数之后接收裁剪时长。
- `-ss` 必须在 FFmpeg 的 `-i` 之前，以便利用输入索引定位。重新编码采用 FFmpeg 的默认精确定位策略，避免从文件开始读取并解码整个前段。
- 裁剪时间参与输出名称、处理参数指纹和 ZIP/PPTX 的处理记录。旧版默认设置生成的输出继续按原处理标记识别。
- 预览帧从临时 PPM 文件读取，读取结束立即删除。实际编码仍依照原有临时文件与输出验证流程执行。
- VP9 的极致压缩档使用 `-deadline best`；其他档位继续使用 `-deadline good`。编码器质量参数以及用户选择的音频码率保持独立。

## 输出格式与竖屏处理

- Windows 和 Linux 的输出容器选择为 MP4、MKV、WebM、原格式四项，旧值 MP4=0 与 SameAsSource=1 保持兼容。新增 MKV=2 和 WebM=3，不增加其他独立输出容器选项。
- 视频编码在界面中按推出时间排列为 H.264、H.265、VP9、AV1、H.266。旧编码枚举数值保持不变，VP9 与 H.266 使用新增数值。
- VP9 使用 `libvpx-vp9`，支持 WebM 和 MKV；H.266 使用 `libvvenc`，必须检查当前 FFmpeg 是否包含该编码器，缺少时禁用选项。H.266 使用 10-bit 像素格式及 QP 质量参数。
- 编码格式与容器不兼容时，界面调整为可用组合；实际 FFmpeg 运行前仍需检查兼容性。
- 分辨率档位根据实际画面方向交换最大宽度与高度。竖屏和横屏均保持原来的宽高比，禁止放大小于目标尺寸的输入。输出验证也需要按画面方向检查尺寸。
- HiDPI 下的队列任务名称、状态、进度条及详细信息分行显示；鼠标选中位置与绘制行高必须使用相同尺寸。界面截图测试应包含不同 DPI 缩放条件。

## 输出容器格式

- 默认输出容器为 MP4；用户也可以选择让每个视频沿用源文件的扩展名和容器格式。
- 源容器模式的输出扩展名必须与源文件一致。输出临时文件也必须保留对应扩展名，以便 FFmpeg 选择正确的封装器。
- 输出编码参数指纹必须包含实际容器扩展名。不同源容器不能因为编码质量参数相同而互相跳过。
- WebM 接受 VP9 与 AV1，音频优先使用 Opus；WMV 不使用 H.265；MOV 不使用 AV1；3GP 仅使用 H.264；OGV 暂不接受当前三种视频编码。
- WMV/ASF 音频使用 WMA，MPEG 程序流使用 MP2，其余常见容器使用 AAC。输出验证必须检查实际容器格式、视频编码、音频编码和处理标记。
- MP4 的 `hvc1`、`av01` 和 `+faststart` 选项只应用于 MOV/MP4 家族容器，不得传给 Matroska、WebM 或其他封装器。

## 音频处理与输出分辨率

- 音频处理方式由共享核心的 `AudioMode` 表示，界面和任务控制层不得自行拼接 FFmpeg 音频参数。
- 默认使用自动编码。自动编码按目标容器选择音频编码器，并使用用户选择的码率。
- 保留原音频时使用 `-c:a copy`，不重新编码；如果目标容器不支持源音频编码，任务应失败并保留原始文件。
- 移除音频时不映射音频流，也不向 FFmpeg 传入音频编码器或码率参数。
- 输出分辨率由共享核心的 `OutputResolution` 表示。六档设置只限制最大宽度和高度，不放大低分辨率源视频，并保持原始宽高比。
- 音频处理方式和输出分辨率必须参与处理参数指纹及输出文件名。修改这两个设置时，必须同步更新转换测试、ZIP/PPTX 测试和编码说明。
- 新参数使用 VideoCompressionWorkbench v3 媒体标记。对于默认音频编码和原始分辨率设置，程序仍识别旧版 FFmpegStudio v2 标记，避免用户已有的默认输出被重复编码。

## 任务列表恢复

- 程序在用户配置目录的 `queue.ffq` 中自动保存待处理输入路径。
- 程序启动时读取任务列表，并使用当前设置重新建立等待处理的任务。任务状态从等待处理开始，已完成的输出由媒体处理标记自动跳过。
- 添加任务、移除任务、清除已完成任务或清空列表后，必须更新自动保存的任务列表。
- 手动导入和导出 `.ffq` 文件仍然保留，方便用户在不同设备间迁移任务。
- 配置目录继续沿用原有名称，以保留旧版本保存的编码设置。

## MP4 文件规则

- MP4 模式下输出扩展名固定为 `.mp4`。
- 转换第一个视频流。音频流按当前音频处理方式映射。
- 自动编码模式使用 AAC 有损音频，默认码率 192 kbit/s；可选择 96、128、160、192、256 或 320 kbit/s。
- 输出像素格式固定为 8-bit `yuv420p`。10-bit 输入会转换为 8-bit。
- 复制元数据和章节。
- 默认不复制字幕流和数据流。
- H.265 输出使用 `hvc1` 标记，AV1 输出使用 `av01` 标记。
- 输出媒体文件在 `comment` 元数据中记录源文件指纹和编码参数指纹。源文件指纹由规范化路径、文件大小和修改时间计算，编码参数指纹包括编码格式、编码设备、质量数值、压缩级别、音频码率和输出容器扩展名。
- 完成任务后保存输入大小和输出大小，界面显示文件大小变化和节省比例。
- 线程数量不写入参数指纹，因为线程分配不会改变用户选择的编码质量参数。

## 批量任务与资源调度

- 单独视频、ZIP 和 PPTX 均作为顶层任务。
- 文件夹输入默认递归扫描，可由用户关闭。
- 同一文件路径在任务列表中只保留一项。
- 任务清单使用 UTF-8 `.ffq` 文本文件，每行记录一个输入路径。
- 编码格式、编码器、CRF、压缩级别、音频码率、并发限制和输出目录保存在用户配置目录中。
- 自动调度根据逻辑 CPU 核心数、可用物理内存、编码器类型和待处理任务数量计算并行任务数及每个 FFmpeg 进程的线程数。
- CPU H.264/H.265 以每个任务约 2 GiB 内存估算；CPU AV1 以约 3 GiB 估算；硬件编码以约 1.5 GiB 估算。
- 自动模式会把全部逻辑 CPU 核心纳入计算，再根据可用内存和任务数量安排并行任务数及每个进程的线程数。
- NVENC、Quick Sync 和 AMF 默认最多并行两个编码任务。
- 每个 FFmpeg 进程必须收到调度器分配的 `-threads:v`。自动分配使用向上取整，尽量让总线程数覆盖全部逻辑 CPU 核心。
- 用户可以将并发任务数限制为 1、2、4 或 8。
- 如果唯一顶层任务是 ZIP/PPTX，内部视频使用调度器计算的并行数；多个顶层任务同时运行时，容器内部视频使用单个工作线程，避免嵌套并发导致过度占用资源。
- 修改任务调度时，必须测试线程数量、手动并发限制、容器内部并行和取消行为。
- 失败或取消的任务可以再次启动；已经完成或跳过的任务不会在重试时重复执行。
- 任务运行期间支持暂停、继续和取消。Linux 通过 `SIGSTOP` / `SIGCONT` 控制 FFmpeg 进程组；Windows 暂时挂起并恢复 FFmpeg 进程的线程。
- 同一批次中不同目录下的同名输入文件必须生成不同的输出路径。

## ZIP 和 PPTX

- ZIP/PPTX 使用 libarchive 读取和生成，不调用 shell 命令解压。
- 解压时拒绝绝对路径、路径穿越、符号链接和硬链接。
- 限制最多 100,000 个条目、单个文件 12 GiB、展开总量 50 GiB。
- ZIP 内视频按当前输出容器设置转换，转换成功后替换原始视频。扩展名发生变化时，更新常见文本、XML、HTML、CSS、JavaScript 和播放列表文件中的路径。
- PPTX 内视频按当前输出容器设置转换。扩展名变化时，更新幻灯片关系文件的 `Target`，并在 `[Content_Types].xml` 中声明相应媒体内容类型。
- ZIP/PPTX 的其他文件应保持原有相对路径。
- 同一压缩包内存在同名但扩展名不同的视频时，输出文件自动添加 `_compressed` 和数字后缀，并分别更新引用路径。
- 任一内部视频转换失败时，放弃当前临时压缩包，保留原始 ZIP/PPTX。
- 重新生成后必须重新读取压缩包。PPTX 还必须检查 `[Content_Types].xml` 和 `ppt/presentation.xml`。
- ZIP/PPTX 内保存输入大小、修改时间和参数指纹。只有输入状态和参数指纹完全一致时，才跳过整个容器任务。
- 修改压缩包处理时，必须测试普通 ZIP、PPTX、扩展名变更、关系文件更新、路径安全和重复处理。

## 输出位置和覆盖规则

- 默认输出到源文件所在目录。
- 输出文件名包含编码格式、编码设备、质量数值、音频码率和压缩级别。
- 用户可以指定统一输出目录。
- 文件夹输入指定输出目录时，默认保留相对于输入文件夹的目录结构。
- 默认不覆盖已有文件。用户启用覆盖后，只有新文件通过检查才会替换旧文件。
- 所有视频和压缩包均先写入临时文件，检查通过后再保存到最终路径。

## 文件安全与任务取消

- 不通过 shell 拼接 FFmpeg 命令。输入路径、输出路径和编码参数必须作为独立进程参数传递。
- Linux 使用 `posix_spawnp`，Windows 使用 `CreateProcessW`。
- 用户取消任务或转换失败时，必须清理临时文件，并保留原始文件。
- 暂停时应暂停 FFmpeg 进程，继续时恢复原进程；取消暂停中的任务时，必须先恢复进程再执行终止操作。
- 修改进程管理代码时，必须测试正常退出、异常退出、暂停、继续和取消行为。

## 应用图标

- 图标资源统一保存在 `assets/icons/`，包括可编辑的 SVG、适用于文档展示的 PNG 和包含多种尺寸的 Windows ICO。
- Windows 资源编译器将 ICO 嵌入主程序，主窗口与 SSH 管理窗口使用该资源显示标题栏和任务栏图标。
- NSIS 安装程序与卸载程序使用同一 ICO 文件。开始菜单、桌面快捷方式和“应用和功能”列表使用主程序的内嵌图标。
- 更换图标时，应同时更新三种资源，并检查 Windows 资源脚本、NSIS 打包参数和 README 的图片引用。

## ZIP/PPTX 文件路径与任务错误信息

- Windows 使用 `archive_read_open_filename_w` 和 `archive_write_open_filename_w` 读取、写入压缩包。Linux 使用平台的原生文件路径接口。压缩包内部文件名和媒体引用保持 UTF-8 编码。
- 从 `std::filesystem::path` 获取压缩包内部的相对路径时，使用 `generic_u8string()`，保留 Unicode 字符并统一采用 `/` 作为路径分隔符。
- 批量任务中的失败原因需要保存在任务对象的 `error` 和 `detail` 中。Windows 任务列表显示失败原因，双击任务可查看完整信息。任务列表在缩放后仍须保留足够的行间距。
- 文件压缩集成测试需要覆盖中文 ZIP/PPTX 输入路径、中文输出路径和压缩包内部中文视频文件名，并验证 PPTX 媒体引用更新。

## Windows 安装和界面规范

- Windows 主程序使用图形子系统。双击启动时不出现控制台窗口；`--encoders`、`--self-test` 等命令仍需保留标准输出与标准错误的重定向能力。
- NSIS 安装程序和卸载程序使用同一产品 ICO。安装向导的欢迎页及页眉图片由 `scripts/generate-windows-installer-art.ps1` 从 PNG 图标生成，使用 24 位 BMP。
- Windows 默认显示输出路径、视频编码、编码设备和质量设置；压缩级别、音频及输出选项可以通过“展开高级设置”使用。任务队列须在普通笔记本窗口高度下可见。
- 任务列表先绘制选中行背景，再绘制任务名称、状态和进度；文字颜色必须保持可辨识。允许通过工具栏、Delete 键删除选中任务，并提供带确认的清空列表操作。删除队列中的任务不应删除原始媒体或已生成的输出文件。
- NVIDIA NVENC 探测使用 640×360 输入及多个视频帧，分别检查 H.264、H.265 和 AV1 编码。隐藏实际不可用的编码器，并将失败原因显示在“检测详情”中。更新驱动程序或显卡首选项后，用户可重新检测。
- Windows 发布前检查应用主程序的图形子系统、应用及安装程序图标、安装向导图像、静默安装、命令行输出、媒体转换和卸载；更新版本号时，同步维护发行说明及开发者文档。

## 编码设置的界面布局

- Windows 和 Linux 均使用双列紧凑布局，短选项组在同一行显示。默认显示输出容器、视频编码、编码设备和目标质量；高级设置中并排显示压缩级别与音频处理、音频码率与输出分辨率。
- 压缩级别采用八个离散位置的滑块，左端为“极速”，右端为“极致压缩”。滑块显示当前档位名称，允许鼠标点击、拖动及方向键调整，Home 和 End 可直接选择两端档位。
- 滑块位置按 0 至 7 映射至原有 `CompressionLevel` 枚举顺序；用户设置、编码参数生成及任务重复处理标记继续使用相同枚举值。修改档位数量或顺序时，必须同步检查两个平台界面的绘制和输入处理。
- 设置面板采用相对于 DPI 缩放的尺寸计算，压缩级别滑块可选择的区域应覆盖整个轨道。任务列表在高级设置展开后仍应保留可操作空间。
- Linux 的界面测试须同时检查默认布局与展开后的布局，并操作压缩级别滑块、方向键、音频处理以及输出分辨率，验证设置能够正确保存。

## 任务队列和信息面板

- 两套原生界面提供“专注处理队列”视图。专注时不绘制编码参数面板，队列使用左侧可用高度，批量处理按钮继续显示；Ctrl+Q 可在两种视图之间切换。
- 任务队列可以选择仅显示失败任务。筛选应在显示任务和计算鼠标选中行时使用相同的条件，切换筛选时清除当前选择与滚动位置。未筛选时可继续查看全部任务。
- 当用户选择任务时，右侧信息面板显示该任务的名称、状态、来源路径、输出位置和错误信息；未选择任务时显示设备及当前编码参数。任务被移除后应恢复默认摘要。
- Linux Xft 界面根据字体测量结果决定文字截断位置，保留完整 UTF-8 字符，避免长文件名、输出目录与按钮标签越过可用显示范围。Windows 使用已有的单行省略显示。
- Esc 用于清除任务选择，Delete 用于移除当前选中的任务；运行中不得删除队列项目。Ctrl+O、Ctrl+D 与 Ctrl+Enter 分别用于添加文件、清除已完成项目和开始批量处理。
- 自动化界面测试覆盖两种布局、任务选择、失败筛选、快捷键及返回设置视图。调整布局时还需检查普通笔记本的屏幕高度和 DPI 缩放。

## 界面维护

- Windows 和 Linux 两套界面必须保持相同的功能和参数含义。
- Windows 必须保留 Per-Monitor V2 DPI 感知、Common Controls v6、Segoe UI 和文件拖放。Windows 11 支持时启用 DWM 圆角与 Mica。
- Linux 界面必须使用 Xft 抗锯齿字体，支持 Xdnd 文件拖放，并根据 `Xft.dpi` 调整缩放。
- Linux 文件选择优先使用 zenity，未安装时尝试 kdialog。两个程序都未安装时，命令行传入路径仍须可用。
- CRF 必须同时支持滑块和数值输入框。
- 任务队列必须提供任务清单导入和导出，并显示每个任务的输入大小、输出大小和节省比例。
- 任务列表必须显示每个独立视频和容器内部视频的状态及进度；总体进度必须根据所有顶层任务计算。
- 选中的任务必须在列表中显示清晰的背景提示。批量任务运行时，界面提供暂停、继续和取消操作。
- 修改布局、控件状态或编码选项时，应同时检查两套平台界面。

## SSH 远程编码

- 远程服务器是视频编码的计算节点。文件选择、输出路径、ZIP/PPTX 展开与重新打包均由本机程序负责。
- 远程服务器当前要求 Linux 或兼容 POSIX shell 的系统，并提供 FFmpeg、ffprobe 和 OpenSSH 服务端。远程 Windows 主机尚未纳入支持范围。
- 本机使用 OpenSSH 客户端的 ssh 和 scp，不部署常驻远程服务，也不要求远程服务器安装本项目。
- SSH 服务器列表来自当前用户的 ~/.ssh/config。解析时必须区分 Host 和 Match 配置段；管理器修改某个别名时，必须保留共享 Host 块中的其他别名、未管理指令和后续 Match 配置段。当前实现尚未展开 Include 指令中的其他配置文件。
- 私钥通过 IdentityFile 或 SSH Agent 使用。密码认证通过 askpass 辅助程序获取密码；Windows 密码保存在 Windows Credential Manager，不写入 SSH 配置或命令行参数。密码在子进程结束后从临时环境变量和环境缓冲区中清除。
- 远程任务为每个转换创建独立权限受限的临时目录。远程输入保留源文件扩展名，远程输出使用所选输出容器扩展名。
- 远程 FFmpeg 的进度通过 SSH 标准输出回传。暂停、继续和取消通过独立 SSH 命令控制远程 FFmpeg 进程。
- 远程输出先由 ffprobe 检查容器、视频编码、音频编码和处理标记，再下载到本机临时文件。只有下载大小检查通过后，才保存到最终输出位置。
- 任务结束时尝试终止远程 FFmpeg 并删除临时目录。连接中断或检查失败时，本机源文件必须保持不变。
- ZIP/PPTX 仅将内部视频送到远程转换；归档展开、媒体引用更新、重新打包和完整性检查仍在本机完成。
- 修改 SSH 认证、远程命令、临时文件管理或取消行为时，必须测试命令参数引用、密码泄露风险、异常断线和远程残留文件。
